以下术语用于描述本规范中的概念。

claim
关于某个subject的断言。
credential
由issuer做出的一组一个或多个claims。 凭证中的claims可以关于不同的subjects。

我们对凭证的定义不同于 NIST 对凭证的定义。

data minimization
将共享数据的数量严格限制在成功完成任务或目标所需的最低限度的行为。
decentralized identifier
一种可移植的基于 URL 的标识符，也称为 DID， 与某个entity相关联。这些标识符最常在verifiable credential中使用， 并与subjects相关联，使得verifiable credential本身可以轻松地从一个 credential repository移植到另一个，而无需重新颁发credential。 DID 的一个示例是 `did:example:123456abcdef`。
decentralized identifier document
也称为 DID document，这是一种可以使用verifiable data registry访问的文档， 包含与特定decentralized identifier相关的信息，例如相关的credential repository和公钥信息。
default graph
包含所有未明确属于named graph的claims的graph。
derived predicate
关于verifiable credential中另一个属性值的可验证布尔断言。这些在零知识证明风格的verifiable presentations中很有用，因为它们可以限制信息披露。 例如，如果verifiable credential包含一个以厘米表示特定身高的属性， 派生谓词可能引用verifiable credential中的身高属性， 证明issuer证实身高值满足最低身高要求，而不实际披露具体的身高值。 例如，subject身高超过 150 厘米。
digital signature
一种用于证明数字消息真实性的数学方案。
entity
任何可以在陈述中作为抽象或具体名词被引用的事物。 实体包括但不限于人、组织、实物、文档、抽象概念、虚构角色和任意文本。 任何实体都可以在生态系统中执行角色，只要它有能力这样做。 请注意，某些实体从根本上无法采取行动，例如字符串 "abc" 无法颁发凭证。
graph
一组声明，形成由subjects及其与其他subjects或数据之间关系组成的信息网络。 每个claim都是图的一部分；在named graphs的情况下这是显式的， 对于default graph则是隐式的。
holder
entity可以通过拥有一个或多个verifiable credentials并从中生成verifiable presentations来执行的角色。 持有者通常（但不总是）是其所持有的verifiable credentials的subject。 持有者将其credentials存储在credential repositories中。
identity
在不同上下文中跟踪entities的手段。数字身份使得能够跨数字上下文跟踪和定制entity交互， 通常使用标识符和属性。身份信息的意外分发或使用可能会损害隐私。 此类信息的收集和使用应遵循data minimization原则。
identity provider
身份提供者，有时缩写为 IdP，是一种用于创建、维护和管理holders身份信息的系统， 同时在联盟或分布式网络中向relying party应用程序提供认证服务。 在这种情况下，holder始终是subject。即使verifiable credentials是不记名credentials， 也假定verifiable credentials保留在subject手中， 如果不是这样，则它们被攻击者窃取了。除非将本文档中的概念与其他规范进行比较或映射， 否则本规范不使用此术语。本规范将identity provider概念解耦为两个不同的概念： issuer和holder。
issuer
entity可以通过对一个或多个subjects断言claims、 从这些claims创建verifiable credential并将verifiable credential传输给holder来执行的角色。
named graph
与特定属性相关联的graph，例如 `verifiableCredential`。这些属性产生单独的graphs， 包含在相应 JSON 对象中定义的所有claims。
presentation
从一个或多个verifiable credentials派生的数据，由一个或多个issuers颁发， 与特定verifier共享。
credential repository
一种程序，例如存储保管库或个人verifiable credential钱包， 用于存储和保护对holders' verifiable credentials的访问。
selective disclosure
holder对共享哪些信息做出细粒度决策的能力。
subject
被做出claims的事物。
user agent
一种程序，例如浏览器或其他 Web 客户端，用于调解holders、issuers和verifiers之间的通信。
validation
确保来自特定issuer的claim满足verifier对特定用途的业务需求。 本规范定义了验证者如何验证verifiable credentials和verifiable presentations。
本规范还规定verifiers在依赖verifiable credentials中的声明之前对其进行验证（确认有效性）。 然而，这种验证（确认有效性）的方式差异很大，超出了本规范的范围。 预期verifiers将信任特定issuers对特定声明的断言， 并应用自己的规则来确定哪些credentials中的哪些声明适合其系统使用。
verifiable credential
可验证凭证是一种具有防篡改特性的凭证，其作者身份可以通过密码学方式验证。 可验证凭证可用于构建verifiable presentations，后者也可以通过密码学方式验证。
verifiable data registry
系统可能执行的一种角色，通过调解标识符、密钥和其他相关数据的创建和verification， 例如verifiable credential模式、撤销注册表、颁发者公钥等， 这些可能是使用verifiable credentials所必需的。 某些配置可能需要subjects的可关联标识符。 某些注册表（例如用于 UUID 和公钥的注册表）可能仅作为标识符的命名空间。
verifiable presentation
可验证展示是一种具有防篡改特性的展示，其编码方式使得数据的作者身份在经过密码学验证过程后可以被信任。 某些类型的可验证展示可能包含从原始verifiable credentials合成的数据， 但不包含原始verifiable credentials本身（例如零知识证明）。
verification
评估verifiable credential或verifiable presentation是否分别是颁发者或展示者的真实且当前的陈述。 这包括检查：凭证（或展示）符合规范；证明方法被满足； 以及（如果存在）状态检查成功。验证凭证并不意味着评估凭证中编码的claims的真实性。
verifier
entity通过接收一个或多个verifiable credentials（可选地包含在verifiable presentation中）进行处理而执行的角色。 其他规范可能将此概念称为relying party。
verification material
可以是密码学公钥或用于验证证明的任何其他数据的信息。
URL
统一资源定位符，如 [[URL]] 所定义。URL 可以被解引用，从而产生资源，例如文档。 解引用或获取 URL 的规则由 URL [=url/scheme=] 定义。 本规范不使用 URI 或 IRI 术语，因为这些术语被认为对 Web 开发者来说容易造成混淆。
