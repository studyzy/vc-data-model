以下术语用于描述本规范中的概念。

声明
关于某个主体的断言。
凭证
由一个或多个声明组成的集合，这些声明由颁发者作出。 凭证中的声明可以关于不同的主体。

我们对凭证的定义不同于 NIST 对凭证的定义。

数据最小化
将共享数据的数量严格限制在成功完成任务或目标所需的最小范围内的行为。
去中心化标识符
一种基于 URL 的可移植标识符，也称为DID，与某个实体相关联。这些标识符通常用于 可验证凭证，并与主体相关联，使得可验证凭证本身可以轻松地从一个存储库迁移到另一个，而无需重新颁发凭证。 一个 DID 示例是 `did:example:123456abcdef`。
去中心化标识符文档
也称为DID 文档，这是一个可以通过可验证数据注册表访问的文档，包含与特定去中心化标识符相关的信息，例如相关的存储库和公钥信息。
默认图
包含所有未明确属于命名图的声明的图。
派生谓词
关于可验证凭证中另一个属性值的可验证布尔断言。这些在零知识证明类型的可验证展示中非常有用，因为它们可以限制信息披露。 例如，如果可验证凭证包含一个以厘米为单位表示特定身高的属性，派生谓词可能引用可验证凭证中的身高属性，证明身高值满足最低身高要求，而无需实际披露具体的身高值。例如，主体的身高超过 150 厘米。
数字签名
一种用于证明数字消息真实性的数学方案。
实体
可以作为抽象或具体名词在语句中引用的任何事物。实体包括但不限于人、组织、物理事物、文档、抽象概念、虚构角色和任意文本。任何实体如果有能力，都可以在生态系统中扮演角色。请注意，有些实体从根本上无法采取行动，例如字符串 "abc" 无法颁发凭证。
图
一组声明，形成由主体及其与其他主体或数据的关系组成的信息网络。每个声明都是图的一部分；在命名图的情况下，这是显式的，而在默认图的情况下，这是隐式的。
持有者
一个实体可能扮演的角色，通过持有一个或多个可验证凭证并从中生成可验证展示。持有者通常但不总是其所持有的可验证凭证的主体。持有者将其凭证存储在凭证存储库中。
身份
在不同上下文中跟踪实体的手段。数字身份通过标识符和属性使得在数字上下文中跟踪和定制实体交互成为可能。身份信息的意外分发或使用可能会危害隐私。此类信息的收集和使用应遵循数据最小化原则。
身份提供者
身份提供者，有时缩写为IdP，是一个用于创建、维护和管理持有者身份信息的系统，同时为联合或分布式网络中的依赖方应用提供身份验证服务。在这种情况下，持有者始终是主体。即使可验证凭证是持有者凭证，也假定可验证凭证仍然与主体在一起，如果不是，则可能被攻击者窃取。本规范仅在将本文档中的概念与其他规范进行比较或映射时使用此术语。本规范将身份提供者概念分解为两个独立的概念：颁发者和持有者。
颁发者
一个实体可以扮演的角色，通过对一个或多个主体作出声明，从这些声明中创建可验证凭证，并将可验证凭证传递给持有者。
命名图
与特定属性（如 `verifiableCredential`）相关联的图。这些属性会生成包含相应 JSON 对象中定义的所有声明的单独图。
展示
从一个或多个可验证凭证中派生的数据，由一个或多个颁发者颁发，与特定验证者共享。
存储库
一种程序，例如存储库或个人可验证凭证钱包，用于存储和保护对持有者可验证凭证的访问。
选择性披露
持有者对共享哪些信息做出细粒度决策的能力。
主体
关于其作出声明的事物。
用户代理
一种程序，例如浏览器或其他 Web 客户端，用于在持有者、颁发者和验证者之间进行通信。
验证
确保来自特定颁发者的声明满足特定用途的验证者的业务需求。本规范定义了验证者如何验证可验证凭证和可验证展示。
它还规定验证者在依赖可验证凭证中的声明之前验证这些声明。然而，这种验证的手段差异很大，超出了本规范的范围。预计验证者会信任某些颁发者的某些声明，并应用自己的规则来确定哪些凭证中的哪些声明适合其系统使用。
可验证凭证
可验证凭证是一种防篡改的凭证，其作者身份可以通过密码学验证。可验证凭证可用于构建可验证展示，这些展示也可以通过密码学验证。
可验证数据注册表
一种系统可能扮演的角色，通过调解标识符、密钥和其他相关数据（如可验证凭证模式、吊销注册表、颁发者公钥等）的创建和验证，这些数据可能是使用可验证凭证所需的。一些配置可能需要主体的可关联标识符。一些注册表（如 UUID 和公钥的注册表）可能仅作为标识符的命名空间。
可验证展示
可验证展示是一种防篡改的展示，以某种方式编码，使得数据的作者身份在密码学验证过程中可以被信任。某些类型的可验证展示可能包含从原始可验证凭证中合成的数据，但不包含原始数据（例如零知识证明）。
验证
评估可验证凭证或可验证展示是否是颁发者或展示者的真实且当前的声明。这包括检查：凭证（或展示）是否符合规范；证明方法是否满足；以及（如果存在）状态检查是否成功。凭证的验证并不意味着对凭证中编码的声明的真实性进行评估。
验证者
一个实体可能扮演的角色，通过接收一个或多个可验证凭证，可选地包含在可验证展示中进行处理。其他规范可能将此概念称为依赖方。
验证材料
可能是密码学公钥或用于验证证明的任何其他数据。
URL
统一资源定位符（Uniform Resource Locator），定义见 [[URL]]。URL 可以被解引用，从而得到资源，例如文档。解引用或获取 URL 的规则由 URL [=url/scheme=] 定义。本规范不使用 URI 或 IRI 术语，因为这些术语被认为会让 Web 开发者感到困惑。
