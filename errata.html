如何提交勘误？

勘误在该工作组 GitHub 仓库的议题列表中提出和存储。添加新勘误的工作流程如下：

  • 针对可能的勘误提出一个议题。该议题的标签应当（SHOULD）设置为"PossibleErratum"。一个勘误可能有多个标签。
  • 社区对该议题进行讨论。如果被确认为真正的勘误，则在条目上添加"Errata"标签，并应移除"PossibleErratum"标签。此外，可以（MAY）在该议题上添加一条新评论，以"Summary:"开头（如果根据讨论内容此类摘要是有用的）。
  • 标记为"Errata"的议题显示在下方。
  • 如果社区拒绝将该议题作为勘误，则应关闭该议题（但不会从下方列表中移除，以确保有历史记录）。
  • 每条勘误也可以标记为"Editorial"；编辑性勘误与实质性勘误分开列出。
  • 所有实质性勘误通常都应有对应的测试，可以是新测试或对现有测试的修改，或者必须（MUST）包含说明为何该勘误不需要更新测试的理由。

本报告包含对所有带有 Errata 标签的未关闭议题的引用。

如果您在遵循此流程时遇到问题，但仍希望报告错误，您也可以联系工作组的 W3C 工作人员联系人 ivan。
