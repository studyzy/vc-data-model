隐私分析

本规范是否涉及个人可识别信息？

是的。可验证凭证中的属性包括个人可识别信息（PII）。

建议：无，因为规范已明确说明这一点。

本规范是否涉及高价值数据？

可能是的。规范对可验证凭证中可以包含的数据没有限制，因此可能包括高度敏感的个人数据。

建议：承载可验证凭证的协议应始终加密可验证凭证的有效负载。此外，包含高度敏感个人数据的可验证凭证应在凭证内部加密这些数据，以防止捕获凭证的任何实体查看敏感信息。

本规范是否为来源引入了跨浏览会话持久的新状态？

本身没有，因为规范仅定义了一个数据结构。然而，使用此规范的协议可能会引入新状态。

建议：无。

本规范是否向 Web 暴露了持久的跨来源状态？

是的。可验证凭证包含一个随机但可能持久的主体标识符。该标识符在颁发者和验证者之间传递。因此，即使可验证凭证本身没有，颁发者和验证者之间的串通也可能使验证者识别主体。这是因为在许多情况下，颁发者会知道主体的完整身份，即使可验证凭证仅包含其中的一小部分（例如年龄）。

建议：持有者应将包含相同 PId 的可验证凭证的分发限制到最少的来源数量。持有者应尽可能获取具有不同 PId 的可验证凭证以发送到不同的来源。

本规范是否向来源暴露了其当前无法访问的其他数据？

是的。可验证凭证的目的是向验证者展示主体的身份属性。然而，请注意，这始终是在主体完全同意的情况下，除非持有者不是主体。在后一种情况下，持有者必须被授权向验证者展示此信息；否则，验证者应拒绝它。

建议：验证者应仅接受来自被授权向其展示可验证凭证的主体或持有者的凭证。

本规范是否启用了新的脚本执行/加载机制？

本身没有，因为规范仅定义了一个数据结构。然而，使用此规范的协议可能会启用脚本加载。

建议：无。

本规范是否允许来源访问用户的位置？

是的。可验证凭证可能包含位置信息，例如主体的家庭地址、电话号码或当前邮寄地址。

建议：无。

本规范是否允许来源访问用户设备上的传感器？

本身没有，因为规范仅定义了一个数据结构。然而，使用此规范的协议可能会启用对用户设备上传感器的访问。

建议：无。

本规范是否允许来源访问用户本地计算环境的某些方面？

本身没有，因为规范仅定义了一个数据结构。然而，使用此规范的协议可能会启用来源访问用户本地计算环境的某些方面。

建议：无。

本规范是否允许来源访问其他设备？

本身没有，因为规范仅定义了一个数据结构。然而，使用此规范的协议可能会启用来源访问其他设备，例如将可验证凭证从一个设备移动到另一个设备。

建议：无。

本规范是否允许来源对用户代理的原生 UI 进行某种程度的控制？

本身没有，因为规范仅定义了一个数据结构。然而，使用此规范的协议可能会启用来源对用户代理的原生 UI 进行某种程度的控制。

建议：无。

本规范是否向 Web 暴露了临时标识符？

可能是的。可验证凭证中的主体 ID 可能是一个临时标识符，不会永久存储在任何地方。

建议：可验证凭证在传输过程中应加密，以避免其内容被窥探。

本规范仅提供了一个数据模型。然而，使用此规范的协议应能够在隐身模式下工作。

建议：无。

本规范是否将数据持久化到用户的本地设备？

可验证凭证的整体生命周期设想它们可能会持久存储在用户的本地设备或用户控制的远程设备上。然而，仅凭可验证凭证本身，如果被恶意实体捕获，除了可能揭示主体的一小部分个人可识别信息（PII）外，对其没有任何价值。

建议：可验证凭证在存储过程中应加密，以防止被攻击者窃取。

是的。

建议：确保它们足够完善。

本规范是否允许降低默认的安全特性？

否。该规范仅定义了一个数据结构和一个签名字段。

建议：无。
